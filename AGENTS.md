
## UI & Visual requirements

- Minimal UI inspired by linear
- No useless components, status indicators next to a status word, self-labeling.
- No repeated UI, every element appears only once.
- No pretend or cosmetic UI. Everything is functional.
- No dishonest animations or states, if something is active, the it is really active.
- Proper tooltips and hints


## Tech requirements

- Strictly typed code with autogenerated schema contracts
- Extensible, modular, anti-drift, anti-dead UI.
- OOP best practices: Depend on interfaces, not on implementations.
- Use of ports and adapters.
- Testable and fully tested: If you are not able to test something because of internet connection, provide the right mock interface.
- You may use third party libraries if it makes the code simpler and more maintainable.
- No fallbacks, no "legacy" support, no "just in case" code. If it is not needed, it is not there. And if it fails, it fails visibly. We don't hide problems.
